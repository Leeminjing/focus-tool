# 后台压缩：停顿、吞吐与恢复验收

日期：2026-10-28；Windows 11、Go 1.26.5、Python 3.12.10。实现来源为 `24f8564` 和 `5483fcc`，使用 Go／Python 标准库、本地工具及确定性控制器，无模型 API。原图模块拓扑保持不变，Patrol 跨 Run 接入仍未完成。

**结果：长时间占用 Engine 锁的同步索引构建已移出，极端调用停顿明显缩短；典型延迟与总吞吐存在取舍。** 四 Context／64 KiB 压力组的端到端 p95 改善；默认 8 MiB 多轮压缩组的最大等待改善，但 p50／p95／p99 及包含排空的总吞吐没有改善，不能概括为普遍提速。

## 实现与正确性

默认 `background`，保留 `-compaction-mode sync` 对照。先封存并同步创建新 WAL，再由唯一 builder 在 Engine 锁外构建索引；索引与 `published.json` 耐久后推进可见水位，最后回收封存段。每条 WAL 变更仍单独 fsync，未引入批量成功确认。

最多一个封存段加一个活动段，均以段目标加至多一个合法帧为正常上界。查询按活动状态／活动缓存／封存缓存／已发布索引取最新值，分页仅从磁盘读取发布水位以内的事实，再拼接较新的缓存事实。积压满时在 Engine 锁外等待，但保留写入顺序；stdio 请求处理仍串行，因此背压可继续影响后续提交和 ack。按记录的索引读写同步和磁盘 I/O 也仍有竞争。详见 [实现合同](background-compaction.md)。

本地已通过：

- [初版完整五步验证](../results/compaction-verification-2026-10-28.json)：Go 全套、vet、26 项 Python 测试、Demo、真实 Focus 三例；[池模式 Focus 三例](../results/compaction-focus-reuse-2026-10-28.json) 另外通过。固定 Focus 源码仍为 `340bf2b8607dfb536d9376d400a02b122a4542bb`，使用现有环境及隔离缓存 PostgreSQL 容器，未修改正式数据库。
- [追加采集预算及失败保存后的四步验证](../results/compaction-verification-final-2026-10-28.json)：Go 全套、vet、**27 项 Python 测试**和 Demo 通过；目录轮转缓存断言适配两段策略后另跑 Run churn 测试通过。
- 七个真实杀进程边界：封存、创建新活动 WAL、部分建索引、建完、耐久发布、可见发布、回收。后五个同时保存了活动 WAL 中更新的结果／ack／版本／关闭状态；重启后验证最新状态优先、旧 ID 不重放、依赖大整数绑定、游标继续读取和 unknown 资源隔离。
- 故意暂停 builder，写满活动段后多次读取快照，确认待处理段／builder 都为 1，字节、缓存条目及写入进度不再增长，而查询和已有结果投递继续。解除暂停后正常排空。快照包含在 Go 原始验证输出中。
- 关闭期限覆盖准入 gate、取消持久化的容量等待和最后 builder join。超时不释放 journal 所有权、不提前释放仍运行任务的资源；后续 Close 会重试未完成取消。已开始的操作系统 fsync 仍不可中断。

标准与需求两轴审查发现并修复了上述关闭边界、并发活动 WAL 恢复覆盖，以及失败轨迹保存缺口；最终无剩余审查阻塞项。

## 采集、超时和统计口径

两个模式均使用相同可信 pooled 工具、四个执行槽／worker、输入、逐次 fsync、执行前权限检查、checkpoint、耐久后续动作及 ack，且读回最终产物。worker 默认 256 次成功调用后回收，两臂相同；长负载中的回收／重新启动成本也计入。预热与最终索引排空在两臂都执行，完整 lifecycle 另含真实 worker／builder 关闭。

主对照三轮交错：1／4 Context 的 64 KiB 段各 240 次，四 Context 的默认 8 MiB 段各 **7296 次**；另有两模式各三组追踪开／关控制，每 trial 120 次。共 **48,096 次测量＋720 次预热＝48,816 次成功调用**。18 个主 trial 共 **138 次压缩**：小段各 9 次自动轮转＋尾部排空，六个默认段 trial 各 **2 次自动轮转＋尾部排空**。没有把“8 MiB 未发生压缩”当作默认段对照。

首次采集在最后一轮同步长负载遇到 30 秒执行准入超时，见 [未完成采集与失败记录](../results/compaction-2026-10-28/README.md)，其数据完全排除于正式统计。正式采集对两臂都显式采用 **300 秒工具和授权等待预算**，用于测量可能超过 30 秒的同步停顿；运行时默认仍为 30 秒，单任务更早的期限仍有效。不能据此声称默认 30 秒条件下长负载全部调用成功。

正式采集独占运行，没有并行本地测试或其他实验。轮间波动明显，下表是三轮**各自指标的中位数**，每轮分位数使用 nearest-rank；不混成一个大分布，不声称统计显著性。吞吐分母包括最后尚未完成的索引排空，逐任务延迟则截止各自 ack。

## 有界性与堆数据

正式长负载中共 336 个周期采样，两臂各 168 个。background 的待处理段与 builder 最大均为 **1**，采样到的活动＋封存序列化字节峰值约 **14.763 MiB**，sync 活动字节峰值约 **7.973 MiB**。background 缓存任务／事实／Run 条目合计峰值 **12,170**。这符合两段策略，而不是用无限后台任务或无限缓存换延迟。每个主 trial 排空后 pending／builder 均为零，退出后的 worker `live/reserved` 均为零。

长负载采样 Go 堆峰值为 sync **7.670 MiB**、background **13.151 MiB**，两段策略有实际额外内存成本；这些采样未强制 GC，也不是进程 RSS。排空后强制 GC，三轮 sync 堆约 **1.149／1.158／1.125 MiB**，background 约 **1.137／1.145／1.107 MiB**。有限样本不能证明长期 RSS 恒定，磁盘事实仍无限期保留。

另外重跑 [完整共享运行时对照与持续负载](../results/compaction-full-runtime-2026-10-28.json)：一轮纠偏场景 barrier 1981.17 ms、event 201.91 ms，包含实际取消回收；[必须完成扫描负对照](../results/compaction-negative-control-2026-10-28.json) 为 1844.14／1841.12 ms，未观察到收益。它们只是兼容性回归，不作为压缩性能证据。1024 次持续任务加 16 条慢消费者事实期间尚未触发默认段压缩，GC 后堆约 **1.081 → 2.695 MiB**，近期缓存保留 1040 个任务／事实；不据此宣称历史或内存恒定。M1 另行重跑，其数字不计入本轮。

轮间与配对扰动明显，部分追踪开组更快，不能声称诊断免费。主对照两臂都开追踪；同客户端高分辨率单调时钟用于速度比较，跨进程 wall 差及 call-minus-body 的负差仍保留为诊断，不裁零。

这一阶段完成了有界后台压缩、耐久发布与切换恢复；没有解决所有 I/O 竞争，也没有建立真实 Agent 的普遍加速结论。下一阶段按计划进入 Patrol：逻辑任务跨 Focus 激活继续执行、结果持久桥接至 Context inbox、后继 Run 消费；并覆盖 checkpoint-before-ack 两个重启点及 queued 恢复的暂停／登记／继续握手。
