# M1 本地对照实验结果

日期：2026-10-27。以下为本机一次完整命令的实测记录，原始数据包含 15 次 trial：每个模式 5 次。

```powershell
go run ./cmd/lab -repeat 5 -passes 256 -out results/m1-2026-10-27.json
```

环境：windows/amd64，go1.26.5；全局执行上限 2；每次扫描 8 MiB 固定文件 × 256 遍 SHA-256。每轮轮换模式顺序，未剔除冷启动试验。编译及生成数据在 trial 计时之外。

| 模式 | 总耗时中位数 ms | 决策中位数 ms | 检查结果消费滞后中位数 ms | 总耗时范围 ms |
|---|---:|---:|---:|---:|
| serial | 1383.36 | 1364.40 | 1352.315 | 1301.02–1684.91 |
| barrier | 1373.53 | 1342.52 | 1329.080 | 1313.53–1426.21 |
| event | 26.12 | 14.34 | 0.000 | 25.15–30.57 |

5 次事件模式均实际启动并取消了扫描进程，取消确认中位数为 1.61 ms；旧扫描结果均被拒收。所有 15 次试验均完成配置修复及读回验证，均拒绝了重复的检查结果。检查完整轨迹确认：同时执行数不超过 2，所有已启动子进程最终都有终态。

结论：在预先定义的“快检查推翻慢扫描”场景里，提前消费结果可提前重规划，省掉剩余扫描，并正确隔离旧计划结果。总耗时包含实际取消确认与配置修复。

收益主要来自撤销不需要的工作。扫描使用固定遍数的真实文件读取和哈希计算，工作量经过人为放大；这不是生产搜索或测试基准，也不代表完整 Agent 或 Focus 的整体加速比例。串行组保留整批消费语义，没有使用检查后直接跳过扫描的专用策略。规则决策没有模型推理时间，缓存、操作系统调度与冷启动会影响数值。

正确性验证：`go test ./...` 和 `go vet ./...` 通过。测试覆盖真实子进程取消并回收、排队取消不启动、并发上限、Context 归属与版本隔离、重复结果去重，以及三种模式的端到端结果一致性。`go test -race ./...` 在当前环境未能运行：Go 提示需要 cgo，且未找到 gcc/clang；不将其记为通过。
