# Research repository

- The architecture image at `docs/images/tool-runtime-original.png` is part of the user's initial requirements and is the architecture acceptance standard. Preserve its module topology: Runs → Focus tool adapter → unified scheduler → Python/process executors → result events and ownership routing → owning Runs. Track incomplete modules explicitly; M1 alone does not complete this architecture.
- Build and experiment entirely locally using Go and Python standard libraries. Do not add model calls, hosted queues, agent frameworks or runtime dependencies without a concrete research need and user agreement.
- Preserve the concurrent barrier baseline. Compare equal inputs, concurrency caps and final outcomes; count cancellation cleanup in total time.
- Never infer that cancellation succeeded from a request alone. Current workers are leaf processes; do not claim process-tree support.
- Record raw traces and distinguish execution facts from result consumption. Version checks and duplicate filtering must be scoped to Context.
- Run `go test ./...` and `go vet ./...` after behavioral changes. Use `go run ./cmd/lab` to reproduce the local experiment.
- The shared architecture lives in `runtime`, `cmd/runtime`, and `python/focus_tool`; preserve `internal/runtime` and `cmd/lab` as the M1 baseline. Register trusted Python or process tools in FocusToolAdapter; never bypass the execution-time authority/lease hook. The caller checkpoints before Run.ack. Test the bridge with `python -m unittest discover -s python/tests -v`; reproduce the full loop with `python examples/demo.py`.
- `python scripts/verify.py` runs the complete local verification. GitHub Actions also runs Linux race detection; local Windows race detection requires a configured cgo compiler.
- Keep measured results separate from performance hypotheses. M1 numbers do not establish real Agent speedup.
- Cancellation must not dequeue an undelivered event. Submission transport failures are acceptance_unknown with the original job identity, never an unqualified rejection; retries reconcile that identity. Global task capacity and per-Run unacked-result quotas are separate. Closing a Run durably transfers remaining facts to runtime_archive without advancing Ack or releasing unknown resources.
- Benchmark the shared runtime with `python benchmarks/full_runtime.py`, including fsync, adapter, actual cancellation and the same final artifact in both arms. Report the negative control and retained-history heap growth; do not present M1 results as new-runtime performance or claim long-running memory stability.
- Optional real Focus tests live in `integration/focus`: use its existing environment and an isolated cached PostgreSQL container, never the desktop database. Fixed source commit, deterministic decision source and untested Patrol/production boundaries must remain explicit.
- Durable history uses bounded active indexes plus a current-WAL-segment cache; every mutation still fsyncs before success. Compaction coalesces derived disk indexes, never execution facts or unknown fences. Keep journal, `.store` and any `.sealed` segment together for stopped backups; memory-only mode is not history-bounded.
- Archive/live recovery pages must obey both count and encoded-byte budgets and preserve owner-scoped high-water cursors through restart. Filter client frames by positive active subscriptions; never retain closed-owner tombstones or terminal retry authorization metadata indefinitely. Reproduce Run churn with `python benchmarks/retention.py` and retain its per-task trace; disk facts intentionally remain unexpired.
- Run `python benchmarks/short_tools.py` alone for performance measurements, then rederive distributions with `benchmarks/analyze_short_tools.py`. Keep exact measurement-window markers, artifact readback, actual compaction/lock intervals and tracing-on/off controls. Cross-process correlation uses same-host Unix timestamps, not unrelated monotonic epochs; do not sum nested spans or silently discard overlapping drain/handler boundaries. Optional trace data never changes WAL success acknowledgements or result ownership.
- Python reuse requires both trusted `ToolDefinition(reuse=True)` registration and a positive runtime worker limit; fresh processes remain the default. One Engine owns its pool. Reserve capacity before the execution-time authority/lease hook, without launching interpreters or sending caller code. Worker lifetime must not inherit a job's cancellation context; failed/cancelled calls retire and reap the worker before releasing resources, never replay automatically. Pool size bounds all interpreter/workspace keys together; cooperative module/output/cwd/background cleanup is not a sandbox or process-tree support.
- Compare fresh/pool with `python benchmarks/short_tools.py --pool-comparison` and equal trusted declarations, inputs, concurrency, fsync and final artifacts. Report cold startup and full shutdown separately from steady state. Very short Go intervals may quantize to zero on Windows: keep signed call-minus-body diagnostics and use high-resolution client monotonic end-to-end measurements for comparisons. Record any post-collection analysis correction separately from immutable raw data and original source fingerprints.
- Background compaction defaults to one sealed overlay plus one bounded active WAL and one builder; keep `-compaction-mode sync` as the comparison baseline. Query active state/cache, sealed cache, then published disk; page disk facts only through the published sequence. Fsync the index and publication marker before advancing visibility and retiring the sealed WAL. Replay sealed before active on restart; immutable sealed corruption fails closed. Capacity waits release Engine.mu while retaining mutation order; trace gate waits separately from real mutex holds. Close deadlines must interrupt gate/capacity/builder waits without abandoning journal ownership, and later Close retries unfinished cancellations.
- Run `python benchmarks/compaction.py` alone for sync/background comparisons, including multi-cycle default 8 MiB segments. Drain warmup and final indexing in both arms to preserve complete measurement windows and include remaining build work. Preserve raw phases, sampling, artifact readback and tracing controls; count backpressure and read/index lock contention, never infer that work outside Engine.mu is free.
- A runtime logical Run may span multiple Focus activations; activation exit never implies Run.close. Long-lived bridges use next_fact (no implicit revision ack), idempotent durable inbox writes and exact typed decision checkpoints plus semantic receipts/action outbox before ack. Recover queued tasks with dispatch paused, original-ID trusted registrations and current authority/lease, then explicit complete-inventory resume; the inventory is not authorization. Optional `integration/focus/run_patrol.py` exercises actual Patrol/Kernel/pool/coordinator/worker components in isolated PostgreSQL; its service-principal lease anchors and deterministic launch/provider adapters remain research-only. Unknown job workspaces require reconciliation before service attachment.
- Automatic Patrol wakes derive from durable unconsumed Context facts, coalesced per Loop; notifications are latency hints. Commit inbox/pending atomically and semantic receipts/outbox/pending progress atomically. Consume only facts represented in the exact native typed inbox snapshot; late/unpaged facts remain pending. Preserve pending while activations or global capacity are busy. Own partial drain tasks independently of wake-driver cancellation, retry completed drain failures, settle all launched activations and aggregate shutdown errors before stopping pumps. Diagnostic observers never change ownership. Loss-of-custody cancellation distinguishes unsubmitted identities and continues all jobs; unknown/cancel_requested never proves cleanup. Reproduce with optional `run_automatic.py` and `test_wake_controls.py` against the pinned Focus environment; production supervisor/service authority and bridge-history retention remain separate work.
